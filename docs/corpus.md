# RealDAE 语料与 `--corpus` 基准

## 语料构成

- **来源**：RealDAE `task_{color,shadow,bleed}_test` 三个退化任务，按文件名排序后
  均匀抽取 17 / 17 / 16 张共 **50 对**，覆盖 0.44–5.24 MP 混合尺寸。
- **命名**：`NN_<type>.webp`（输入）+ `NN_gt.webp`（配对基准真值），NN 为原文件名
  字母序的自增编号；`manifest.json` 记录每张的 `w`/`h`。
- **压缩**：webp q85、长边 ≤2600（原始 jpg/png ~153MB → ~36MB 入库）。
- **重新生成**：`dotnet run tools/gen_corpus.cs <RealDAE根目录> <输出目录>`
  （SkiaSharp file-based 脚本，同参数会产出同一批图）。

## 怎么读（计时口径）

`dotnet run --project bench/Sdcb.GcdrNet.Benchmark -c Release -- --corpus vulkan`

- **按 manifest 序号 01→50 处理**（不按尺寸排序）：大小图交错，池驱逐/重建
  被真实负载放大，更接近生产环境；**01_color 仅作全局 warmup 不计时**，
  其余 49 张逐张计时。
- **解码在计时外**（SkiaSharp webp→bgr 先完成再开表）；输出**不编码**（无 u8→文件）。
- 计时的就是 `Enhance` 端到端：上传 → bgr2nchw 预处理 → GC-Net → div6 六通道
  拼装 → DR-Net → 后处理/读回。
- 每个新尺寸第一次计时**包含该尺寸 pipeline 的编译+显存分配**（冷管线）；
  同尺寸（相同 W×H）复跑命中池是热管线。NN 序下 5MP 档同尺寸组内
  ~80ms（热）与 ~250ms（冷）的差异即此。
- **第二遍**全量重跑并逐张比对采样输出 hash——输出确定性回归（曾用来实锤
  图缓存复活 UAF：pass1/pass2 同一图产生不同稳态输出）。
- **PSNR/MAE 对照 `NN_gt.webp` 是数据集真值**，衡量的是**模型能力上限**，
  不是实现忠实度（实现 oracle 是 ORT 生成的 golden fixtures，u8 ≤2）。个别
  图 ~11dB 是模型对该样本的能力边界，不是 bug。
- **内存**：引擎初始化前后 + 每张图后采样 working set（逐图 `ws` 列；汇总
  ΔWS = loaded→pass1 末张、peak = 全部采样最大值）/ managed delta / `VkDevice` live+peak
  （单点计数 `vkAllocateMemory`，直接反映 worker arena 驻留）。harness 的源图/输出/真值三块
  BGR 缓冲只增不减地复用，否则每张 5 MP 图 ~45 MB 的 LOH 垃圾会在 gen2 GC 前堆进 working set，
  把引擎自己的占用淹没。
- **池统计**：`pools created / workers / evicted`——CPU 按尺寸建池、按估算字节预算驱逐
  （~1KB/px），50 个不同尺寸下驱逐是常态；Vulkan worker 与尺寸无关（只增不减的 arena，
  换尺寸只重录命令缓冲），只有 1 个池、不驱逐。下方结果段落是复用前的历史记录。

## 环境变量

| 变量                | 作用                                             |
| ------------------- | ------------------------------------------------ |
| `GCDR_FROM`         | 从第 N 张开始（默认 1，跳过 warmup 后）          |
| `GCDR_ONLY`         | 按文件名子串过滤                                 |
| `GCDR_DUMP`         | 把每张 BGR 输出落盘到指定目录                    |
| `GCDR_INTER=1`      | 记录 gcIn/gcOut/drIn 中间量 hash，pass2 报分歧层（gc 与 dr 共用一块 arena 后 gcIn/gcOut 读到的是被 dr 覆盖后的内容，只有 drIn 仍有意义） |
| `GCDR_DUMPPIPE=1`   | 配合 INTER，输出 pipeline/arena 诊断             |
| `GCDR_ZERO_ARENA=1` | 管线录制前 `vkCmdFillBuffer` 清零 arena          |

## 结果（RTX 3080 Ti + 16 线程 AVX2，NN 序）

```
corpus[vulkan] 49 timed images: 7273.3 ms total, 25.21 MP/s, mean 148.4 ms
  2nd pass: 11247.5 ms total, 16.30 MP/s (delta = per-size pipeline creation -3974 ms, -55%)
  psnr mean 24.65 dB over 49 images
  pools: 70 size pools created (70 workers), 69 evicted
  mem: managed +323 MB, workingset +0 MB, vkDevice live 4867 MB (peak 5283 MB)
corpus[cpu]    49 timed images: 89201.7 ms total, 2.06 MP/s, mean 1820.4 ms
  2nd pass: 89439.5 ms total, 2.05 MP/s (delta = per-size pipeline creation -238 ms, -0%)
  psnr mean 24.65 dB over 49 images
  pools: 132 size pools created (132 workers), 130 evicted
  mem: managed -162 MB, workingset +0 MB
```

NN 序下 **pass2 比 pass1 更慢**（尺寸交错导致池几乎无命中，驱逐-重建持续
发生）——这正是真实负载的表现；CPU 的 session 编译几乎免费，两遍持平。
vk/cpu 输出 hash 不同属预期（实现不同，容差内），PSNR 一致。
