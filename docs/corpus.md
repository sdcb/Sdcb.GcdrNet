# RealDAE 语料与 `--corpus` 基准

## 语料构成

- **来源**：RealDAE `task_{color,shadow,bleed}_test` 三个退化任务，按文件名排序后
  均匀抽取 17 / 17 / 16 张共 **50 对**，覆盖 0.44–5.24 MP 混合尺寸。
- **命名**：`NN_<type>.webp`（输入）+ `NN_gt.webp`（配对基准真值），NN 为原文件名
  字母序的自增编号；`manifest.json` 记录每张的 `w`/`h`。
- **压缩**：webp q85、长边 ≤2600（原始 jpg/png ~153MB → ~36MB 入库）。
- **重新生成**：`dotnet run tools/gen_corpus.cs <RealDAE根目录> <输出目录>`
  （SkiaSharp file-based 脚本，同参数会产出同一批图）。

## 怎么读（计时口径）

`dotnet run --project bench/Sdcb.GcdrNet.Benchmark -c Release -- --corpus vulkan`

- **按像素数升序**处理；**第 1 张仅作全局 warmup 不计时**，其余 49 张逐张计时。
- **解码在计时外**（SkiaSharp webp→bgr 先完成再开表）；输出**不编码**（无 u8→文件）。
- 计时的就是 `Enhance` 端到端：上传 → bgr2nchw 预处理 → GC-Net → div6 六通道
  拼装 → DR-Net → 后处理/读回。
- 每个新尺寸第一次计时**包含该尺寸 pipeline 的编译+显存分配**（冷管线）；
  同尺寸（相同 W×H）复跑命中池是热管线。表中 5MP 档 ~80ms 与 ~250ms 的差异
  即此（冷管线增量 ≈ +160–180ms）。
- **第二遍**全量重跑并逐张比对采样输出 hash——输出确定性回归（曾用来实锤
  图缓存复活 UAF：pass1/pass2 同一图产生不同稳态输出）。
- **PSNR/MAE 对照 `NN_gt.webp` 是数据集真值**，衡量的是**模型能力上限**，
  不是实现忠实度（实现 oracle 是 ORT 生成的 golden fixtures，u8 ≤2）。个别
  图 ~11dB 是模型对该样本的能力边界，不是 bug。
- **内存**：managed delta / working-set delta / `VkDevice` live+peak
  （单点计数 `vkAllocateMemory`，直接反映池化 pipeline 驻留）。
- **池统计**：`pools created / workers / evicted`——池按估算字节预算驱逐
  （~1KB/px/pipeline），50 个不同尺寸下驱逐是常态。

## 环境变量

| 变量 | 作用 |
|---|---|
| `GCDR_FROM` | 从第 N 张开始（默认 1，跳过 warmup 后） |
| `GCDR_ONLY` | 按文件名子串过滤 |
| `GCDR_DUMP` | 把每张 BGR 输出落盘到指定目录 |
| `GCDR_INTER=1` | 记录 gcIn/gcOut/drIn 中间量 hash，pass2 报分歧层 |
| `GCDR_DUMPPIPE=1` | 配合 INTER，输出 pipeline/arena 诊断 |
| `GCDR_ZERO_ARENA=1` | 管线录制前 `vkCmdFillBuffer` 清零两个 arena |
